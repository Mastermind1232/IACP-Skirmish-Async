🎲 Imagine playing Imperial Assault with no round tracker on the board. Every time someone needs to know what round it is, they count every card played, every figure activated, and independently figure it out. Sometimes two players get different answers.

Real bug this caused:
Recovery looked at the flags and concluded "we're in the card-draw phase" — but the game was actually in deployment zone selection. It sent card-draw prompts at the wrong time, confusing both players.

Root cause: There was no single "phase" label. Recovery had to guess from flags, and it guessed wrong.

Duplicated guessing

4 different systems each maintain their own checklist to figure out the same thing — "what phase are we in?"

Silent disagreements

When two systems guess differently, there's no error — one just quietly does the wrong thing (like the bug above).

🎯 Now there's a round tracker on the board. Every time the game advances, the tracker moves to the next phase. When any system needs to know "what phase are we in?" — it just reads the tracker. No guessing.

The game now tracks its phase explicitly

lobby→ map selection→ initiative→ zone selection→ deployment→ attachment→ card draw→ round active→ ended
Within "round active", a sub-tracker:
start of round→ activation→ end of round ↻ repeat

How this fixes the bug

Phase = "zone selection"
→
Recovery checks phase Phase is "zone selection" → skip card-draw recovery entirely Bug is impossible now — structurally prevented

One answer, always

The phase is stored once and read everywhere. No system can "get a different answer" because they all read the same field.

Recovery is scoped

Recovery only runs the checks that make sense for the current phase. Card-draw recovery can't accidentally fire during zone selection.

🚀 The round tracker was step one. The long-term vision is a full game log system. Instead of just tracking where the game is, record every move that happened. Then any display — Discord, a website, a replay viewer — can reconstruct the game from that log.

How it would work

Player does something "Deploy Vader to B4", "Attack with Jyn", "End turn"
↓
Game engine (pure rules, no Discord) Validates the action, produces events
↓

Discord botMessages & buttons

Spectator modeRead-only view

Recovery = just replay

If something goes wrong, replay the event log from the beginning. No more 13 hand-written recovery functions — the log is the recovery.

Undo = rewind the log

Instead of carefully restoring snapshots, just drop the last event and re-derive the game state. Simple and bulletproof.

Test without Discord

The game rules become a self-contained engine. You can test every rule, every card, every interaction — without needing Discord at all.

Multiple UIs from one source

Discord is just one way to view the game. The same event log could power a web app, a mobile viewer, or a tournament replay tool.
